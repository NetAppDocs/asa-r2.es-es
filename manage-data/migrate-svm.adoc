= Migrar una máquina virtual de almacenamiento de un clúster ASA a un clúster ASA r2
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
A partir de ONTAP 9.18.1, puedes migrar sin interrupciones una máquina virtual de almacenamiento (VM) desde cualquier clúster ASA estándar a cualquier clúster ASA r2 para adoptar la arquitectura simplificada y optimizada de los sistemas ASA r2 en entornos solo SAN.


NOTE: No puedes migrar una máquina virtual de almacenamiento desde un ASA MetroCluster a un clúster ASA r2. Los sistemas ASA r2 no admiten configuraciones MetroCluster.

Los sistemas ASA r2 son compatibles con la tecnología QuickAssist (QAT). Los sistemas ASA no son compatibles con QAT. A partir de ONTAP 9.20.1, ONTAP reduce la elevada latencia de lectura y el uso de la CPU que pueden producirse tras la migración de una máquina virtual (VM) de almacenamiento desde un sistema ASA (sin QAT) a un sistema ASA r2 (con QAT).

La migración de máquinas virtuales de almacenamiento entre sistemas de almacenamiento ASA y ASA r2 se admite de la siguiente manera:

[cols="2"]
|===
| Desde cualquiera de los siguientes sistemas ASA : | A cualquiera de los siguientes sistemas ASA r2:

* ASA C400
* ASA C250
* ASA A900
* ASA A800
* ASA A400
* ASA A250
* ASA A150

* ASA AFF A700
* ASA AFF A400
* ASA AFF A250

 a| 
* ASA A1K

* ASA A70

|===
Para obtener la lista más actualizada de sistemas ASA y ASA r2, consultelink:https://hwu.netapp.com/["NetApp Hardware Universe"^] .  Los sistemas ASA r2 aparecen en NetApp Hardware Universe como "ASA Serie A/Serie C (Nuevo)".

Solo es posible migrar una máquina virtual de almacenamiento a un clúster ASA r2 desde un clúster ASA. No se admite la migración desde ningún otro tipo de sistema ONTAP a un sistema ASA r2.

.Antes de empezar
Todos los nodos del clúster ASA r2 y del clúster ASA deben estar ejecutando ONTAP 9.18.1 o posterior.  Las versiones de parches de ONTAP 9.18.1 en los nodos del clúster pueden variar.



[[step-1-verify-the-status-of-the-asa-storage-vm]]
== Paso 1: Verifique el estado de la máquina virtual de almacenamiento ASA.

Antes de migrar una máquina virtual de almacenamiento desde un sistema ASA , no debe haber espacios de nombres NVMe ni vVols presentes y cada volumen en la máquina virtual de almacenamiento debe contener solo un LUN.  No se admite la migración de espacios de nombres NVMe ni de vVols .  La arquitectura de los sistemas ASA r2 requiere que los volúmenes contengan un único LUN.

.Pasos
. Verifique que no haya espacios de nombres NVMe presentes en la máquina virtual de almacenamiento:
+
[source, cli]
----
vserver nvme namespace show -vserver <storage_VM>
----
+
Si se muestran entradas, los objetos NVMe deben serlink:https://docs.netapp.com/us-en/ontap/nvme/convert-namespace-to-lun-task.html["convertido"^] a LUN o eliminados.  Ver el `vserver nvme namespace delete` y el `vserver nvme subsystem delete` comandos en ellink:https://docs.netapp.com/us-en/ontap/concepts/manual-pages.html["Referencia de comandos del ONTAP"^] Para obtener más información.

. Verifique que no haya vVols presentes en la máquina virtual de almacenamiento:
+
[source, cli]
----
lun show -vserver <storage_VM> -class protocol-endpoint,vvol
----
+
Si existen vVols , deben copiarse a otra máquina virtual de almacenamiento y luego eliminarse de la máquina virtual de almacenamiento que se va a migrar.  Ver el `lun copy` y `lun delete` comandos en ellink:https://docs.netapp.com/us-en/ontap/concepts/manual-pages.html["Referencia de comandos del ONTAP"^] Para obtener más información.

. Verifique que cada volumen en la máquina virtual de almacenamiento contenga un único LUN:
+
[source, cli]
----
lun show -vserver <storage_VM>
----
+
Si un volumen contiene más de un LUN, utilice el `volume create` y `lun move` comandos para crear una relación volumen-LUN de 1:1. Ver ellink:https://docs.netapp.com/us-en/ontap/concepts/manual-pages.html["Referencia de comandos del ONTAP"^] Para más información.



.¿Cuál es el siguiente?
Ya está listo para crear una relación de pares de clúster entre sus clústeres ASA y ASA r2.



[[step-2-create-a-cluster-peer-relationship-between-your-asa-and-asa-r2-clusters]]
== Paso 2: Cree una relación de pares de clúster entre sus clústeres ASA y ASA r2.

Antes de poder migrar una máquina virtual de almacenamiento de un clúster ASA a un clúster ASA r2, es necesario crear una relación de pares.  Una relación entre pares define las conexiones de red que permiten a los clústeres ONTAP y a las máquinas virtuales de almacenamiento intercambiar datos de forma segura.

.Acerca de esta tarea
El clúster ASA es el clúster _de origen_ desde el que se migrará la máquina virtual de almacenamiento, y el clúster ASA r2 es el clúster _de destino_ al que se migrará la máquina virtual de almacenamiento.

.Antes de empezar
Debe haber creado LIF intercluster en cada nodo de los clústeres que se están interconectando utilizando uno de los siguientes métodos.

* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-share-data-ports-task.html["Configure las LIF intercluster en los puertos de datos compartidos."^]
* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-use-dedicated-ports-task.html["Configure las LIF intercluster en puertos de datos dedicados."^]
* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-use-ports-own-networks-task.html["Configurar LIF entre clústeres en espacios IP personalizados"^]


.Pasos
. En el clúster de destino, crea una relación entre iguales con el clúster de origen y genera una frase de contraseña:
+
[source, cli]
----
cluster peer create -peer-addrs <source_cluster_LIF_IPs> -generate-passphrase
----
+
El siguiente ejemplo crea una relación de pares de clúster entre el clúster 1 y el clúster 2 y crea una contraseña generada por el sistema:

+
[listing]
----
cluster1::> cluster peer create -peer-addrs 10.98.191.193 -generate-passphrase
Passphrase: UCa+6lRVICXeL/gq1WrK7ShR
            Peer Cluster Name: cluster2
            Initial Allowed Vserver Peers: -
            Expiration Time: 6/7/2017 09:16:10 +5:30
            Intercluster LIF IP: 10.140.106.185
Warning: make a note of the passphrase - it cannot be displayed again.

----
. Copie la frase de contraseña generada.
. En el clúster de origen, crea una relación entre iguales con el clúster de destino:
+
[source, cli]
----
cluster peer create -peer-addrs <destination_cluster_LIF_IPs>
----
. Introduce la frase de contraseña generada en el clúster de destino.
. Verifique que se haya creado la relación de pares del clúster:
+
[source, cli]
----
cluster peer show
----
+
El siguiente ejemplo muestra el resultado esperado para clústeres emparejados correctamente.

+
[listing]
----
cluster1::> cluster peer show

Peer Cluster Name   Cluster Serial Number   Availability   Authentication
-----------------   ---------------------   -------------- --------------
cluster2             1-80-123456             Available      ok
----


.Resultado
Los clústeres ASA y ASA r2 están interconectados y los datos de las máquinas virtuales de almacenamiento se pueden transferir de forma segura.

.¿Cuál es el siguiente?
Ya estás listo para realizar la comprobación previa a la migración.



[[step-3-execute-the-migration-pre-check]]
== Paso 3: ejecutar la comprobación previa a la migración

Antes de migrar una máquina virtual de almacenamiento de un clúster ASA a un clúster ASA r2, debes realizar una comprobación previa a la migración y solucionar cualquier problema necesario. No podrás realizar la migración hasta que la comprobación previa se complete correctamente.

.Acerca de esta tarea
El clúster ASA es el clúster _de origen_ desde el que se migrará la máquina virtual de almacenamiento, y el clúster ASA r2 es el clúster _de destino_ al que se migrará la máquina virtual de almacenamiento.

.Paso
. Desde tu clúster de destino, ejecuta la comprobación previa a la migración:
+
[source, cli]
----
vserver migrate start -vserver <storage_VM> -source-cluster <sourcecluster> -check-only true
----
+
Si necesitas solucionar algún problema para preparar la migración, se muestran tanto el problema como la medida correctiva. Soluciona el problema y repite la comprobación previa hasta que se complete con éxito.



.¿Cuál es el siguiente?
Ya está listo para migrar su máquina virtual de almacenamiento desde su clúster ASA a un clúster ASA r2.



[[step-4-migrate-an-asa-storage-vm-to-an-asa-r2-cluster]]
== Paso 4: Migrar una máquina virtual de almacenamiento ASA a un clúster ASA r2

Una vez que haya preparado su clúster ASA y creado la relación de pares de clúster necesaria con el clúster ASA r2, puede comenzar la migración de la máquina virtual de almacenamiento.

Al realizar una migración de máquina virtual de almacenamiento, es una buena práctica dejar un 30 % de margen de CPU tanto en el clúster ASA como en el clúster ASA r2 para permitir que se ejecute la carga de trabajo de la CPU.

.Acerca de esta tarea
* Tras la migración de la máquina virtual de almacenamiento, la E/S del cliente se transfiere de forma fluida al clúster de destino sin interrupciones y la máquina virtual de almacenamiento del clúster ASA r2 se elimina automáticamente. La transición automática y la eliminación automática de la máquina virtual de almacenamiento están habilitadas de forma predeterminada. Si lo deseas, puedes desactivar una o ambas opciones y realizarlas manualmente.
* El clúster ASA es el clúster _de origen_ desde el que se migrará la máquina virtual de almacenamiento, y el clúster ASA r2 es el clúster _de destino_ al que se migrará la máquina virtual de almacenamiento.


.Antes de empezar
* El clúster ASA r2 debe tener suficiente espacio libre para alojar la máquina virtual de almacenamiento migrada.
* Si la máquina virtual de almacenamiento ASA contiene volúmenes cifrados, el administrador de claves integrado o el administrador de claves externo en el sistema ASA r2 debe configurarse a nivel de clúster.
* Las siguientes operaciones no pueden ejecutarse en el clúster ASA de origen:
+
** Operaciones de conmutación por error
** WAFLIRON
** Huella dactilar
** Transferencia de volumen, rehosting, clonación, creación, conversión o análisis




.Pasos
. Desde el clúster de destino, inicia la migración de la máquina virtual de almacenamiento:
+
[source, cli]
----
vserver migrate start -vserver <storage_VM_name> -source-cluster <source_cluster>
----
+
Para desactivar la transición automática, usa el parámetro  `-auto-cutover false`. Para desactivar la eliminación automática de la máquina virtual de almacenamiento de origen, usa el parámetro  `-auto-source-cleanup false`.

. Supervisar el estado de la migración
+
[source, cli]
----
vserver migrate show -vserver <storage_VM_name>
----
+
Si necesita pausar o cancelar la migración antes de que comience el cambio automático, utilice la siguiente opción: `vserver migrate pause` y el `vserver migrate abort` comandos.  Debes pausar la migración antes de cancelarla.  No se puede cancelar la migración una vez que haya comenzado el cambio.

+
Si la transición automática está activada, cuando se complete la migración, el *status* se muestra como *migration-complete*. Si la transición automática está desactivada, el *status* se muestra como *Ready for source cleanup*.



.Resultado
La máquina virtual de almacenamiento se migra del clúster ASA al clúster ASA r2.  El nombre y el UUID de la máquina virtual de almacenamiento, el nombre de la LIF de datos, la dirección IP y los nombres de los objetos, como el nombre del volumen, permanecen sin cambios.  Se actualiza el UUID de los objetos migrados en la máquina virtual de almacenamiento.

.¿Cuál es el siguiente?
Si has desactivado la transición automática y la eliminación automática de la máquina virtual de almacenamiento, realiza la transición y la limpieza posteriores a la migración para pasar manualmente tus clientes ASA a tu clúster de destino y eliminar la máquina virtual de almacenamiento del clúster ASA.



[[step-5-post-migration-cutover-and-cleanup]]
== Paso 5: transición y limpieza tras la migración

Durante una migración entre clústeres de una máquina virtual de almacenamiento, las operaciones de E/S de los clientes se transfieren al clúster de destino y la máquina virtual de almacenamiento del clúster de origen se elimina automáticamente. Si decides desactivar la transición automática y la eliminación de la máquina virtual de almacenamiento de origen durante la migración, deberás realizar estos pasos manualmente una vez que el estado de la migración alcance *Ready for source cleanup*.



[[manually-cut-over-clients-after-a-storage-vm-migration]]
=== Realiza manualmente la transición de los clientes después de una migración de una máquina virtual de almacenamiento

Si desactivas la transición automática de clientes durante la migración entre clústeres de una máquina virtual de almacenamiento, una vez que la relación de migración esté lista para la transición, realiza la transición manualmente para que la máquina virtual de almacenamiento de destino pueda servir datos a los clientes.

.Acerca de esta tarea
Realiza esta tarea desde el clúster de destino.

.Pasos
. Ejecuta manualmente la transición del cliente:
+
[source, cli]
----
vserver migrate cutover -vserver <storage_VM_name>
----
. Verifique que la operación de migración se haya completado:
+
[source, cli]
----
vserver migrate show
----


.Resultado
Los datos se sirven a tus clientes desde la máquina virtual de almacenamiento de tu clúster de destino.

.El futuro
Ya estás listo para eliminar la máquina virtual de almacenamiento del clúster de origen.



[[manually-remove-a-storage-vm-after-migration]]
=== Eliminar manualmente una máquina virtual de almacenamiento tras la migración

Si desactivas la limpieza automática del origen durante una migración de una máquina virtual de almacenamiento entre clústeres, una vez finalizada la migración, elimina la máquina virtual de almacenamiento del clúster de origen para liberar el espacio de almacenamiento.

.Antes de empezar
Tus clientes deberían estar sirviendo datos desde el clúster de destino.

.Pasos
. Desde el clúster de origen, comprueba que el estado de la VM de almacenamiento de origen sea *Ready for source cleanup*:
+
[source, cli]
----
vserver migrate show
----
. Elimina la máquina virtual de almacenamiento de origen:
+
[source, cli]
----
vserver migrate source-cleanup -vserver <storage_VM_name>
----


.Resultado
Se ha eliminado la máquina virtual de almacenamiento de tu clúster de origen.
