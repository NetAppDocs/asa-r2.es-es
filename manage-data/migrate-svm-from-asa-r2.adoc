= Migrar una VM de almacenamiento de un clúster ASA r2 a un clúster ASA o AFF
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
A partir de ONTAP 9.20.1, puedes migrar sin interrupciones una máquina virtual de almacenamiento (VM) de un clúster ASA r2 de 2 nodos a un clúster ASA de 2 nodos o a un clúster AFF de 2 nodos. Puede que necesites migrar una máquina virtual de almacenamiento para consolidar cargas de trabajo SAN y NAS, adoptar funciones de ONTAP que no están disponibles para los sistemas ASA r2 o actualizar tu hardware. Las asignaciones de host y las configuraciones existentes de unidades de almacenamiento para LUNs y espacios de nombres se mantienen durante la migración, lo que reduce el esfuerzo operativo y el riesgo.

.Antes de empezar
* Debes ser administrador del clúster.
* Todos los nodos de ambos clústeres deben ejecutar ONTAP 9.20.1 o una versión posterior.


.Acerca de esta tarea
* Solo es posible migrar una máquina virtual de almacenamiento ASA r2 desde un clúster ASA r2 de 2 nodos a un clúster AFF de 2 nodos.
+
** No es posible migrar una máquina virtual de almacenamiento ASA r2 a un clúster FAS, ni a un clúster ASA o AFF con más de dos nodos.
** No es posible migrar una máquina virtual de almacenamiento ASA r2 desde un clúster ASA r2 con más de dos nodos.


* La migración de datos de un clúster ASA r2 a un clúster AFF no es reversible.
+
Puedes cancelar una migración antes de la transición, pero una vez iniciada esta, no podrás interrumpirla ni revertirla. Una vez completada la migración, no podrás migrar datos de un clúster AFF a un clúster ASA r2.

+
Puedes link:migrate-svm.html["migrar una VM de almacenamiento de un ASA a un clúster ASA r2"].

* Solo puedes migrar una máquina virtual de almacenamiento cada vez.
* La máquina virtual de almacenamiento puede contener un máximo de 400 unidades de almacenamiento.
* La VM de almacenamiento no puede contener unidades de almacenamiento de destino de SnapMirror.




[[step-1-create-a-cluster-peer-relationship]]
== Paso 1: Crear una relación de paridad entre clústeres

Antes de poder migrar una máquina virtual de almacenamiento desde un clúster ASA r2, necesitas crear una relación entre iguales. Una relación entre iguales define las conexiones de red que permiten a los clústeres ONTAP y a las máquinas virtuales de almacenamiento intercambiar datos de forma segura.

.Acerca de esta tarea
En el procedimiento siguiente, el clúster ASA o AFF es el clúster de _destino_ y el clúster ASA r2 es el clúster de _origen_.

.Antes de empezar
Debe haber creado LIF intercluster en cada nodo de los clústeres que se están interconectando utilizando uno de los siguientes métodos.

* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-share-data-ports-task.html["Configure las LIF intercluster en los puertos de datos compartidos."^]
* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-use-dedicated-ports-task.html["Configure las LIF intercluster en puertos de datos dedicados."^]
* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-use-ports-own-networks-task.html["Configurar LIF entre clústeres en espacios IP personalizados"^]


.Pasos
. En el clúster de destino, crea una relación entre iguales con el clúster de origen y genera una frase de contraseña:
+
[source, cli]
----
cluster peer create -peer-addrs <source_cluster_LIF_IPs> -generate-passphrase
----
+
El siguiente ejemplo crea una relación de pares de clúster entre el clúster 1 y el clúster 2 y crea una contraseña generada por el sistema:

+
[listing]
----
cluster1::> cluster peer create -peer-addrs 10.98.191.193 -generate-passphrase
Passphrase: UCa+6lRVICXeL/gq1WrK7ShR
            Peer Cluster Name: cluster2
            Initial Allowed Vserver Peers: -
            Expiration Time: 6/7/2017 09:16:10 +5:30
            Intercluster LIF IP: 10.140.106.185
Warning: make a note of the passphrase - it cannot be displayed again.

----
. Copie la frase de contraseña generada.
. En el clúster de origen, crea una relación entre iguales con el clúster de destino:
+
[source, cli]
----
cluster peer create -peer-addrs <destination_cluster_LIF_IPs>
----
. Introduce la frase de contraseña generada en el clúster de destino.
. Verifique que se haya creado la relación de pares del clúster:
+
[source, cli]
----
cluster peer show
----
+
El siguiente ejemplo muestra el resultado esperado para clústeres emparejados correctamente.

+
[listing]
----
cluster1::> cluster peer show

Peer Cluster Name   Cluster Serial Number   Availability   Authentication
-----------------   ---------------------   -------------- --------------
cluster2             1-80-123456             Available      ok
----


.Resultado
Los clústeres tienen una relación de paridad entre clústeres. Los datos de las VM de almacenamiento se pueden transferir de forma segura.

.¿Cuál es el siguiente?
Ya estás listo para preparar tu VM de almacenamiento ASA r2 para la migración.



[[step-2-prepare-the-asa-r2-storage-vm-for-migration]]
== Paso 2: preparar la máquina virtual de almacenamiento ASA r2 para la migración

Antes de migrar una máquina virtual (VM) de almacenamiento desde un clúster ASA r2, tienes que eliminar las relaciones de replicación y de sincronización activa de SnapMirror y hacer varias comprobaciones.

.Pasos
. link:../data-protection/snapmirror-active-sync-break-relationship.html["Elimina cualquier relación de replicación existente"].
. link:../data-protection/snapmirror-active-sync-delete-relationship.html["Elimina cualquier relación existente de SnapMirror active sync"].
. Comprueba si IPsec está activado:
+
[source, cli]
----
security ipsec config show
----
+
.. Si IPsec está activado, desactívalo:
+
[source, cli]
----
security ipsec config modify -is-enabled -false
----
+
Más información sobre el comando link:https://docs.netapp.com/us-en/ontap-cli/security-ipsec-config-show.html["security ipsec config show"^].

.. Comprueba si hay LIF de IPv6 y de IP virtual (VIP):
+
[source, cli]
----
network interface show -vserver <storage_vm_name> -fields address-family, is-vip
----
+
Para los LIF de IPv6, el parámetro  `-address-family` es  `ipv6`. Para los LIF VIP, el parámetro  `-is-vip` es  `true`.

.. Si existe algún LIF de IPv6 o VIP, elimínalos:
+
[source, cli]
----
network interface delete -vserver <storage_vm_name> - lif <lif_name>
----
.. Comprueba que no queden LIF de IPv6 ni VIP en la VM de almacenamiento:
+
[source, cli]
----
network interface show -vserver <storage_VM_name>
----
+
Obtén más información sobre los comandos link:https://docs.netapp.com/us-en/ontap-cli/network-interface-show.html["network interface show"^] y link:https://docs.netapp.com/us-en/ontap-cli/network-interface-delete.html["network interface delete"^].



. Comprueba si hay algún grupo de interfaces configurado:
+
[source, cli]
----
network port ifgrp show
----
+
.. Si se han configurado grupos de interfaces, comprueba si alguna LIF de la VM de almacenamiento está vinculada a un grupo de interfaces:
+
[source, cli]
----
network interface show -vserver <storage_VM_name> -fields home,node, home-port, curr-node, curr-port
----
.. Si una LIF de la VM de almacenamiento está vinculada a un grupo de interfaces, migra la LIF a otro puerto físico:
+
[source, cli]
----
network interface migrate -vserver <storage_VM_name> -lif <LIF> -des-node <destination_node> -dest-port <destination_port>
----
+
Más información sobre el comando link:https://docs.netapp.com/us-en/ontap-cli/network-port-ifgrp-show.html["network port ifgrp show"^].





.¿Cuál es el siguiente?
Ya estás listo para realizar la comprobación previa a la migración.



[[step-3-execute-the-migration-pre-check]]
== Paso 3: ejecutar la comprobación previa a la migración

Antes de migrar una máquina virtual de almacenamiento desde un clúster ASA r2, debes realizar una comprobación previa a la migración y solucionar cualquier problema necesario. No podrás llevar a cabo la migración hasta que la comprobación previa se complete correctamente.

.Paso
. Desde tu clúster de destino, ejecuta la comprobación previa a la migración:
+
[source, cli]
----
vserver migrate start -vserver <storage_VM> -source-cluster <sourcecluster> -check-only true
----
+
Si necesitas solucionar algún problema para preparar la migración, se muestran tanto el problema como la medida correctiva. Soluciona el problema y repite la comprobación previa hasta que se complete con éxito.



.¿Cuál es el siguiente?
Ya estás listo para migrar tu máquina virtual de almacenamiento desde tu clúster ASA r2.



[[step-4-migrate-a-storage-vm-from-an-asa-r2-cluster]]
== Paso 4: migrar una máquina virtual de almacenamiento desde un clúster ASA r2

Una vez que hayas creado la relación de paridad entre clústeres necesaria entre los clústeres ASA r2 y ASA o AFF, y hayas completado los pasos para preparar ambos clústeres, podrás iniciar la migración de la VM de almacenamiento.

Como práctica recomendada, deja un margen del 30 % de CPU tanto en el clúster ASA r2 como en el clúster AFF para que la carga de trabajo de migración pueda ejecutarse.

.Acerca de esta tarea
* Tras la migración de la máquina virtual de almacenamiento, la E/S del cliente se transfiere de forma fluida al clúster de destino sin interrupciones y la máquina virtual de almacenamiento del clúster ASA r2 se elimina automáticamente. La transición automática y la eliminación automática de la máquina virtual de almacenamiento están habilitadas de forma predeterminada. Si lo deseas, puedes desactivar una o ambas opciones y realizarlas manualmente.
* El clúster ASA es el clúster _de origen_ desde el que se migrará la máquina virtual de almacenamiento, y el clúster ASA r2 es el clúster _de destino_ al que se migrará la máquina virtual de almacenamiento.


.Pasos
. Desde el clúster de destino, inicia la migración de la máquina virtual de almacenamiento:
+
[source, cli]
----
vserver migrate start -vserver <storage_VM_name> -source-cluster <source_cluster>
----
+
Para desactivar la transición automática, usa el parámetro  `-auto-cutover false`. Para desactivar la eliminación automática de la máquina virtual de almacenamiento de origen, usa el parámetro  `-auto-source-cleanup false`.

. Supervisar el estado de la migración
+
[source, cli]
----
vserver migrate show -vserver <storage_VM_name>
----
+
Si necesita pausar o cancelar la migración antes de que comience el cambio automático, utilice la siguiente opción: `vserver migrate pause` y el `vserver migrate abort` comandos.  Debes pausar la migración antes de cancelarla.  No se puede cancelar la migración una vez que haya comenzado el cambio.

+
Si la transición automática está activada, cuando se complete la migración, el *status* se muestra como *migration-complete*. Si la transición automática está desactivada, el *status* se muestra como *Ready for source cleanup*.



.Resultado
La máquina virtual de almacenamiento se migra del clúster ASA r2 al clúster de destino.

.¿Cuál es el siguiente?
Si has desactivado la transición automática y la eliminación automática de la máquina virtual de almacenamiento, realiza la transición y la limpieza posteriores a la migración para conmutar manualmente tus clientes de ASA r2 al clúster de destino y eliminar la máquina virtual de almacenamiento del clúster de ASA r2.



[[step-5-post-migration-cutover-and-cleanup]]
== Paso 5: transición y limpieza tras la migración

Durante una migración entre clústeres de una máquina virtual de almacenamiento, las operaciones de E/S de los clientes se transfieren al clúster de destino y la máquina virtual de almacenamiento del clúster de origen se elimina automáticamente. Si decides desactivar la transición automática y la eliminación de la máquina virtual de almacenamiento de origen durante la migración, deberás realizar estos pasos manualmente una vez que el estado de la migración alcance *Ready for source cleanup*.



[[manually-cut-over-clients-after-a-storage-vm-migration]]
=== Realiza manualmente la transición de los clientes después de una migración de una máquina virtual de almacenamiento

Si desactivas la transición automática de clientes durante la migración entre clústeres de una máquina virtual de almacenamiento, una vez que la relación de migración esté lista para la transición, realiza la transición manualmente para que la máquina virtual de almacenamiento de destino pueda servir datos a los clientes.

.Acerca de esta tarea
Realiza esta tarea desde el clúster de destino.

.Pasos
. Ejecuta manualmente la transición del cliente:
+
[source, cli]
----
vserver migrate cutover -vserver <storage_VM_name>
----
. Verifique que la operación de migración se haya completado:
+
[source, cli]
----
vserver migrate show
----


.Resultado
Los datos se sirven a tus clientes desde la máquina virtual de almacenamiento de tu clúster de destino.

.El futuro
Ya estás listo para eliminar la máquina virtual de almacenamiento del clúster de origen.



[[manually-remove-a-storage-vm-after-migration]]
=== Eliminar manualmente una máquina virtual de almacenamiento tras la migración

Si desactivas la limpieza automática del origen durante una migración de una máquina virtual de almacenamiento entre clústeres, una vez finalizada la migración, elimina la máquina virtual de almacenamiento del clúster de origen para liberar el espacio de almacenamiento.

.Antes de empezar
Tus clientes deberían estar sirviendo datos desde el clúster de destino.

.Pasos
. Desde el clúster de origen, comprueba que el estado de la VM de almacenamiento de origen sea *Ready for source cleanup*:
+
[source, cli]
----
vserver migrate show
----
. Elimina la máquina virtual de almacenamiento de origen:
+
[source, cli]
----
vserver migrate source-cleanup -vserver <storage_VM_name>
----


.Resultado
Se ha eliminado la máquina virtual de almacenamiento de tu clúster de origen.
